# v55 — entry_type discipline + evidence_type rename

> **Note (2026-07-03, issue #273 audit):** the original v55 description
> claimed a SQL `CHECK (entry_type IN (...))` constraint was added to
> `soldiers.entry_type`. The inline `CREATE TABLE soldiers` at
> `internal/db/schema.go:25-65` declares `entry_type TEXT NOT NULL
> DEFAULT 'soldier'` — **no CHECK constraint at the SQL level**. The
> comment at `schema.go:824-836` explicitly documents this as the
> "pragmatic approach": v55 added application-level validation
> + a log table (via `migrateEntryTypeDiscipline`) but no SQL
> CHECK. This doc is updated to reflect the actual SQL effect.
> Per the audit's reversibility table at
> `docs/migrations/reversibility.md` Block 16, the SQL effect is
> **Reversible** at the SQL level (only the log table was created).

- Add application-level `entry_type` discipline: a new helper
  `migrateEntryTypeDiscipline` (`internal/db/schema.go:842`) creates
  the `soldiers_entry_type_check_log` table (single `applied_at`
  primary key) and inserts a sentinel `CURRENT_TIMESTAMP` row. The
  helper is idempotent (the `sqlite_master` existence check
  short-circuits re-runs). Application-level validation in
  `internal/records/` and `internal/appshell/` rejects INSERTs
  with `entry_type` outside the four valid values.
- Rename `research_log.evidence_type = 'archive'` → `'local_archive'`
  to align with the glossary (an evidence-type value should be
  unambiguous; the bare word "archive" is a category, not a value).
  The forward path tolerates a missing `research_log` table
  (`isNoSuchTableError` fallback) so v55 applies cleanly to archives
  that predate the table.
- Add `internal/models/constants.go` exporting `EntryTypeSoldier`,
  `EntryTypeWife`, `EntryTypeWidow`, `EntryTypeLinkedPerson`, and
  `EvidenceTypeLocalArchive` so templates and viewmodels stop scattering
  string literals.

This bump is the data-model prerequisite for the Tier 2 Soldier →
PersonRecord rename (issue #97). After v97 lands, the constants will
keep the new names stable.

Manual steps: none. Existing archives migrate transparently because
application-level validation is permissive of all currently-valid
entry types and the `archive` → `'local_archive'` UPDATE rewrites
the one column value in place.

Rollback: per the audit, the v55 SQL effect is Reversible — the
`migrate down` runner drops the `soldiers_entry_type_check_log`
table. The `research_log` rename is a separate Irreversible block
(Block 17 in the catalogue) that the runner refuses to undo without
`--force-irreversible` + a restore-point ID.
