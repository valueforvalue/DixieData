## Generated file policy: gitignored or checked in?

Decision: **gitignored**, regenerated by `make tpl` (analogous
to `internal/templates/*_templ.go`). The generated file is
`internal/releasehistory/baked.go` containing:

```go
// Code generated by scripts/bake-release-notes.sh. DO NOT EDIT.
package releasehistory

var baked []Entry // parsed from CHANGELOG.md at release time
```

When the binary is built without a bake (the dev workflow,
where the user is iterating on a feature), `baked` is nil and
the About page's Release history section renders the empty
state: "Release history not yet generated for this build. Run
`make tpl` to bake from CHANGELOG.md."

The Makefile target `release-notes-bake` regenerates the file.
A CI gate (`scripts/release-github.ps1` Gate 6 — new) ensures
the bake runs before the release tag is created.

## Risks

- CHANGELOG.md is 6,500+ lines. The parser must handle the
  pre-#266 `## v1.2.N` shape AND the post-#266 `## v1.U.N`
  shape. Both tested in slice 2.
- The `release/DixieData-release-v{VERSION}.zip` archive is
  built per the release script; the bake step inserts before
  the zip is built (so the zip's embedded binary carries the
  correct baked content).
- The first run after this lands will have `baked == nil` in
  the dev binary until `make tpl` runs. The empty-state copy
  must read naturally — not "error: missing data."
