# Plan — issue #581, Slice 3: iCalendar microcopy audit (audit-only)

This plan covers **Slice 3 of issue #581** — the audit-only
sealing of the iCalendar export's user-facing copy via a new
format-aware regression probe. **No code edits are planned:** the
slice's job is to lock the surface (frozen changeset) so future
contributors cannot drift the calname, SUMMARY, DESCRIPTION, or
alarm copy without breaking the probe.

Slice 1 (Static Archive HTML) shipped in `ed37efd`. Slice 2
(Typst PDF) shipped in `822b40b`. Slice 4 (runtime frontend +
server + startup + CLI) is out of scope here.

## Why this is its own slice

**#581 locked decision 4**: "Format-specific rules or manual review
are acceptable where HTML-oriented `.templ` rules do not safely
translate." iCalendar has its own RFC 5545 grammar + calname /
SUMMARY / DESCRIPTION / VALARM contracts. The existing three probes
do not apply. A format-aware probe is required to seal the
surface, and the audit is half-rendered (the actual user sees the
copy in a calendar client, not in raw `.ics` bytes), so the probe
must also assert what the imported-calendar view shows.

**YAGNI verified (per `docs/agents/pragmatic-principles.md` §1):**
a previous Plan-proposal would have included 3 microcopy edits;
recon showed all 3 are either already correctly handled
(`SoldierDisplayName` fallback in `peopleinfo.SoldierDisplayName`)
or intentionally retained per user direction. The slice shrinks
to its smallest sufficient shape — probe + docs + audit commit.

## Surface inventory (verified by direct read)

iCalendar copy lives in one place per the export pipeline:

`internal/archive/export_service.go::ExportICalendar` (lines
1280–1356) is the only production code path that emits iCalendar
text. Helpers it composes from:

| Function (line) | User-facing copy it produces |
|---|---|
| `iCalendarManagedSummary` (1594) | `SUMMARY:` line per VEVENT — drives calendar entry titles |
| `iCalendarManagedDescriptionLines` (1606) | `DESCRIPTION:` lines per VEVENT — drives long description body |
| `iCalendarAlarmLines` (1624) | `VALARM` block body — drives reminder text |
| `compactICalendarDescriptionLines` (1584) | compaction helper, no copy of its own |
| `ExportICalendar` top-level (1283+) | `X-WR-CALNAME:DixieData Memorial Anniversaries` + `PRODID:-//{AppName} v{AppVersion}//Memorial Anniversaries v{N}//EN` |

The summary builder switches on `preferences.TitlePreset`:

| TitlePreset value | SUMMARY shape |
|---|---|
| `CalendarEventTitlePresetNameLead` (default) | `"{name} — Memorial Anniversary"` |
| (other presets) | ... |

The description builder emits up to 5 lines:

- `Record ID: {Display ID}` (when `IncludeRecordID`)
- `Unit: {Unit}` (when `IncludeUnit`)
- `Buried In: {BuriedIn}` (when `IncludeBuriedIn`)
- `Original Death Date: {DeathDate}` (when `IncludeOriginalDate`)
- `Generated by DixieData.` (always — terminator)

The alarm builder emits `Upcoming memorial anniversary for {name}`
when the reminder is > 60 minutes before the event, otherwise
`Memorial anniversary in one hour for {name}`.

**No other Go file emits iCalendar text** (verified by
`grep -rn 'X-WR-\|VEVENT\|SUMMARY:\|DESCRIPTION:' --include='*.go' internal/`).
CLI dispatch in `internal/appshell/cli_export.go::runExportICalendar`
and Wails dispatch in `internal/appshell/exports_handlers.go::handleExportICalendar`
are thin wrappers; the user-facing CLI copy ("export ical", "usage")
is slice-4 territory.

## Slice decomposition (one commit = one reviewable unit)

### Slice 3A — Probe + driver wiring + GREEN-on-HEAD fixtures

**Goal**: ship the probe pinning each catalogued iCalendar copy
verbatim, BEFORE any future drift can land. The probe exits 0 on
the current repo (GREEN-on-HEAD, not RED — the slice is
audit-only, not fix). The `--strict` gate then prevents future
drift.

**Files added**:

- `audit/smoke_icalendar_microcopy.mjs` — format-aware probe.
  Walks `internal/archive/export_service.go` for the canonical
  iCalendar-copy strings. Asserts:
  - **Required copy** (flagged when missing — must remain present):
    `X-WR-CALNAME:DixieData Memorial Anniversaries`,
    `PRODID:-//…//Memorial Anniversaries v{…}//EN`,
    `"{name} — Memorial Anniversary"` SUMMARY format,
    `"Record ID: "` / `"Unit: "` / `"Buried In: "` /
    `"Original Death Date: "` DESCRIPTION lines,
    `"Generated by DixieData."` trailing attribution,
    `"Upcoming memorial anniversary for "` / `"Memorial
    anniversary in one hour for "` VALARM body strings.
  - **Forbidden copy** (flagged when present — must NOT appear):
    non-canonical "event" / "record" synonyms in calname
    (`Memorial Anniversary` is glossary-correct per `CONTEXT.md`),
    conflicting SUMMARY phrasings (`"Birthday"`, `"Death
    Anniversary"`, `"Memorial Day for "`).
  - **Imported-calendar check**: calname does NOT exceed the
    iOS Calendar 64-byte truncation limit; SUMMARY does NOT
    exceed Apple Calendar's soft warning length.
  - Exclusion: byte-level helpers (`writeICalendarLine`,
    `icalText`), envelope extensions (`X-DIXIEDATA-*`), UID
    generation, the CSV / JSON / JPG paths.
  - Mirrors the slice-1 / slice-2 probe shape: `ICS_SOURCE`
    env override (file path; the probe reads the raw Go
    source and asserts each required substring is present
    in `ExportICalendar` or in the helper functions).
- `audit/smoke_icalendar_microcopy.test.mjs` — 12 assertions:
  4 GREEN-on-HEAD (probe exits 0, summary present, each
  required string is present in current repo, forbidden
  patterns absent), 6 per-rule synthetic positives (a
  synthetic Go source missing each canonical string makes
  the probe exit 1), 2 strict-mode flips.
- `Makefile`: add `lint-icalendar-microcopy`, `…-strict`,
  `…-test`.
- `.github/workflows/test.yml`: add all three to the audit
  step.
- `docs/agents/ux-microcopy.md`: new "iCalendar coverage
  (issue #581)" paragraph mirroring the Static Archive + PDF
  prose.

**Per `docs/agents/tdd.md`**: the GREEN-on-HEAD assertions ARE
the acceptance criterion. The slice is GREEN when
`node audit/smoke_icalendar_microcopy.test.mjs` is green on
HEAD with `--strict` exiting 0.

**No Go-side edits** — the slice is audit + regression net
only. Existing `internal/archive/export_service_test.go`
substring assertions (`Grouped by` row 1612, etc.) continue
to guard the byte contract; no new Go tests land in this
slice because no behavior changes.
